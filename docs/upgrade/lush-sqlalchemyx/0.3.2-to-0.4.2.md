# Upgrade Guide: lush-sqlalchemyx 0.3.2 → 0.4.2

## 版本变更

| 版本 | 变更 |
|------|------|
| 0.3.3 | 修复软删除 Session 钩子注册机制 + `get_by_id`/`exists`/`ret_dto_after_get_by_id` `is_delete` 守卫 |
| **0.4.0** | **破坏性变更** — `SoftDeleteTableMixin` 分离为协议层 + 实现层 |
| 0.4.1 | 依赖: `lush-dal-protocol>=0.2.2` |
| **0.4.2** | **破坏性变更** — 移除 import 时 `@sa_event.listens_for` 隐式钩子注册，`setup_dal_hooks()` 成为唯一注册入口 |

## 0.4.2 破坏性变更

### `@sa_event.listens_for` 隐式注册移除

**旧行为** (0.4.1): `import lush_sqlalchemyx` 时会通过 `@sa_event.listens_for` 装饰器自动在 `SyncSession` 上注册三个事件监听器（软删除拦截、软删除查询过滤、只读保护）。

**新行为** (0.4.2): 装饰器已移除，必须**显式调用** `setup_dal_hooks()` 注册：

```python
from lush_sqlalchemyx import setup_dal_hooks
setup_dal_hooks()
```

不调用则软删除、只读保护等 Session 事件钩子不会生效。

### 按框架的调用指引

**Flask** — 使用 `LushFlaskSQLAlchemy.init_db()` 自动注册，无需手动调用：

```python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from lush_sqlalchemyx.integrations.flask.ext import LushFlaskSQLAlchemy

app = Flask(__name__)
db = SQLAlchemy()
LushFlaskSQLAlchemy(db)  # init_db() 内部自动调用 setup_dal_hooks()
```

**FastAPI** — 在 `lifespan` 中调用：

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
from lush_sqlalchemyx import setup_dal_hooks

@asynccontextmanager
async def lifespan(app: FastAPI):
    setup_dal_hooks()
    yield

app = FastAPI(lifespan=lifespan)
```

**直接使用 DAL** — 在创建 Session 前调用一次：

```python
from lush_sqlalchemyx import setup_dal_hooks
setup_dal_hooks()

# 之后正常创建 Session 和使用 DAL
session = Session(engine)
```

### 模型注册时序说明

**在任何时机调用 `setup_dal_hooks()` 均可**，模型类（继承 `SoftDeleteTableMixin` / `ReadOnlyMixin`）的定义可在调用之前或之后。因为钩子注册在 `SyncSession` 上，在 **flush/query 时**通过 `isinstance` 和 `with_loader_criteria` 动态评估。

已验证的场景：

| 场景 | 时序 | 说明 |
|------|------|------|
| A | `setup_dal_hooks()` → import models | 模拟 FastAPI lifespan 先行注册 |
| B | import models → `setup_dal_hooks()` → DB ops | 模型模块级导入，app init 时注册 |
| C | 跨文件模型定义，两阶段混合 | 同一进程内两种时序均正常（幂等） |

### 迁移步骤

1. 搜索项目中是否有直接 `import lush_sqlalchemyx` 后依赖自动钩子生效的代码
2. 在 Flask `LushFlaskSQLAlchemy.init_db()` 或 FastAPI `lifespan` 中添加 `setup_dal_hooks()` 调用
3. 纯 DAL 使用场景在创建 Session 前调用一次 `setup_dal_hooks()`
4. 提交前运行 `just test-one lush-sqlalchemyx` 确认覆盖率和功能正常

## 0.4.0 破坏性变更

### SoftDeleteTableMixin 拆分为两层

**旧代码** (0.3.x):

```python
from lush_sqlalchemyx.base.dal import SoftDeleteTableMixin

class MyTable(Base, SoftDeleteTableMixin):
    ...
```

**新代码** (0.4.0):

```python
from lush_sqlalchemyx.base.dal import FieldIsDeleteSoftDeleteTableMixin

class MyTable(Base, FieldIsDeleteSoftDeleteTableMixin):
    ...
```

仅需 rename `SoftDeleteTableMixin` → `FieldIsDeleteSoftDeleteTableMixin`。

### 方法重命名

| 旧方法 | 新方法 |
|--------|--------|
| `.delete(is_delete=1)` | `.soft_delete()` |
| `.delete(n)` | 不再支持自定义值，仅 `soft_delete()` (设置 1) |
| `.undelete()` | `.soft_undelete()` |

### 自定义软删除列

`SoftDeleteTableMixin` 现在是纯协议基类，不强制任何 DB 列：

```python
from lush_sqlalchemyx.base.dal import SoftDeleteTableMixin

class MyTable(Base, SoftDeleteTableMixin):
    __soft_delete_column__ = "deleted_at"

    deleted_at: Mapped[datetime | None] = mapped_column(
        sa.DateTime, nullable=True, default=None
    )

    @property
    def is_soft_deleted(self) -> bool:
        return self.deleted_at is not None

    def soft_delete(self) -> None:
        self.deleted_at = datetime.now()

    def soft_undelete(self) -> None:
        self.deleted_at = None
```

自定义列类型 + `do_orm_execute` hook 动态过滤、`get_by_id`/`exists` identity map 守卫全部自动适配。

## 0.3.3 问题修复

### Session 钩子未注册 → 静默物理删除（严重）

修复前：`import lush_sqlalchemyx` 依赖 `@sa_event.listens_for` 自动注册（0.4.2 后改为显式注册）。

### get_by_id/exists 软删后不一致

`session.get()` 命中 identity map 时，已软删实体被错误返回。现通过 `entity.is_soft_deleted` 守卫。

## 新增公开 API

| 函数 | 说明 |
|------|------|
| `setup_dal_hooks()` | 一次调用注册所有必要钩子（幂等） |
| `register_soft_delete_hooks()` | 显式注册软删除钩子（幂等） |
| `unregister_soft_delete_hooks()` | 注销软删除钩子（幂等） |
| `is_soft_delete_hooks_registered()` | 检查钩子是否已注册 |
| `FieldIsDeleteSoftDeleteTableMixin` | 标准 `is_delete` 列实现层 |
