# Upgrade Guide: lush-sqlalchemyx 0.4.2 → 0.6.0

## 版本变更

| 版本 | 变更 |
|------|------|
| **0.6.0** | **破坏性变更** — 移除 `Std*` 预设业务字段类；新增 `MySQLPoolConfig` 可配置连接池；清理 `shortcuts/meta.py` 业务字段排序；`FieldIsDeleteSoftDeleteTableMixin.is_delete` 列类型从 `Integer` 改为 `SmallInteger` |

## 破坏性变更

### 1. 移除 `Std*` 预设业务字段类

以下类已被移除（原已标记 `deprecated`）：

| 被移除的类 | 替代方案 |
|---|---|
| `StdBaseCU` | 继承 `BaseCU`，自行声明需要的字段 |
| `StdBaseDTO` | 继承 `BaseDTO`，自行声明需要的字段 |
| `StdAsyncBaseTable` | 继承 `BasicAsyncBaseTable`，自行声明需要的字段 |
| `StdReadOnlyBasicAsyncBaseTable` | 继承 `ReadOnlyBasicAsyncBaseTable`，自行声明需要的字段 |
| `StdSyncBaseTable` | 继承 `BasicSyncBaseTable`，自行声明需要的字段 |
| `StdReadOnlySyncBaseTable` | 继承 `ReadOnlySyncBaseTable`，自行声明需要的字段 |

**旧代码** (0.4.2):

```python
from lush_sqlalchemyx.base.dal import StdAsyncBaseTable, StdBaseCU, StdBaseDTO

class MyTable(StdAsyncBaseTable):
    __tablename__ = "my_table"
    name: Mapped[str] = mapped_column(sa.String(50))
    # create_operator_id, update_operator_id, is_delete 自动来自 StdAsyncBaseTable

class MyCU(StdBaseCU["MyTable"]):
    _Table = MyTable
    name: str
    # create_operator_id, update_operator_id 自动来自 StdBaseCU
```

**新代码** (0.6.0):

```python
from lush_sqlalchemyx.base.dal import BaseCU, BaseDTO, BasicAsyncBaseTable

class MyTable(BasicAsyncBaseTable):
    __tablename__ = "my_table"
    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(sa.String(50))
    # 自行声明所需业务字段
    create_operator_id: Mapped[int] = mapped_column(sa.Integer, default=0)
    is_delete: Mapped[int] = mapped_column(sa.SmallInteger, default=0)

class MyCU(BaseCU["MyTable"]):
    _Table = MyTable
    name: str
    create_operator_id: int = 0
```

**迁移步骤**:
1. 将所有 `StdAsyncBaseTable` 替换为 `BasicAsyncBaseTable`，手动添加 `id` 主键和其他需要的字段
2. 将所有 `StdBaseCU` 替换为 `BaseCU`，手动添加业务字段
3. 将所有 `StdBaseDTO` 替换为 `BaseDTO`，手动添加 `id` 和业务字段
4. 删除所有 `Std*` import 语句

---

### 2. MySQL 连接池默认值可配置

`AsyncMySQLManager` 和 `SyncMySQLManager` 新增 `pool_config` 参数，支持三级定制：

**class-level 子类化：**

```python
from dataclasses import dataclass, field
from lush_sqlalchemyx.mgrs.mysql import AsyncMySQLManager, MySQLPoolConfig

@dataclass
class MyPoolConfig(MySQLPoolConfig):
    pool_size: int = field(default=50)
    max_overflow: int = field(default=100)

class MyManager(AsyncMySQLManager):
    _default_pool_config = MyPoolConfig
```

**实例级传入：**

```python
mgr = AsyncMySQLManager(
    "mysql+aiomysql://user:pass@localhost/db",
    pool_config=MySQLPoolConfig(pool_size=10, pool_recycle=7200),
)
```

**逐参覆盖（向后兼容）：**

```python
mgr = AsyncMySQLManager("mysql+aiomysql://user:pass@localhost/db", pool_size=10)
```

---

### 3. `shortcuts/meta.py` 清理 DDL 字段排序偏好

`TableDDLInfo.print_sql()` 不再重排字段顺序（移除了将 `id`/`create_datetime`/`create_operator_id`/`update_datetime`/`update_operator_id`/`is_delete` 提到前面的业务偏好逻辑）。

---

### is_delete 列类型变更

**旧代码** (0.4.2):

```python
class FieldIsDeleteSoftDeleteTableMixin(SoftDeleteTableMixin):
    is_delete: Mapped[int] = mapped_column(sa.Integer, default=0, comment="逻辑删除")
```

**新代码** (0.6.0):

```python
class FieldIsDeleteSoftDeleteTableMixin(SoftDeleteTableMixin):
    is_delete: Mapped[int] = mapped_column(sa.SmallInteger, default=0, comment="逻辑删除")
```

**影响范围**：
- 所有继承 `FieldIsDeleteSoftDeleteTableMixin` 的表
- 所有继承 `StdSyncBaseTable` 或 `StdAsyncBaseTable` 的表（它们内部继承了 `FieldIsDeleteSoftDeleteTableMixin`）

**变更原因**：
- `is_delete` 字段只存储 0 和 1 两个值，`Integer`（4字节）浪费空间
- `SmallInteger`（2字节）足够使用，节省一半存储空间
- `SmallInteger` 是 SQLAlchemy 标准类型，跨数据库兼容（MySQL/PostgreSQL/SQLite）

## 迁移步骤

### 1. 升级依赖

```toml
# pyproject.toml
dependencies = [
    "lush-sqlalchemyx>=0.6.0,<0.7.0",
]
```

### 2. 数据库迁移（必须）

**对于已有表**，需要执行 DDL 修改列类型：

#### MySQL

```sql
-- 对所有使用软删除的表执行
ALTER TABLE <your_table> MODIFY COLUMN is_delete SMALLINT NOT NULL DEFAULT 0;
```

#### PostgreSQL

```sql
-- 对所有使用软删除的表执行
ALTER TABLE <your_table> ALTER COLUMN is_delete TYPE SMALLINT;
```

#### SQLite

SQLite 没有真正的类型系统，无需迁移。

### 3. 代码变更（必须）

**不再使用 `Std*` 类**，改为继承基础类 + 自行声明字段：

```python
# 旧: 依赖 StdAsyncBaseTable 自动提供 create_operator_id, is_delete 等
# 新: 继承 BasicAsyncBaseTable, 显式声明所需字段

from lush_sqlalchemyx.base.dal import BasicAsyncBaseTable, BaseCU, BaseDTO
from sqlalchemy.orm import Mapped, mapped_column
import sqlalchemy as sa

class MyTable(BasicAsyncBaseTable):
    __tablename__ = "my_table"
    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(sa.String(50))
    create_operator_id: Mapped[int] = mapped_column(default=0)
```

## 兼容性说明

### 向后兼容

- **Python API**：完全兼容，无需修改代码
- **数据库数据**：`Integer` 和 `SmallInteger` 存储的 0/1 值完全兼容
- **ORM 行为**：完全兼容，无行为变更

### 不兼容点

- **数据库 Schema**：已有表的 `is_delete` 列类型需要手动迁移
- **新建表**：自动使用 `SmallInteger`，无需额外操作

## 降级/回退

如果需要回退到 0.4.2：

```toml
dependencies = [
    "lush-sqlalchemyx>=0.4.2,<0.5.0",
]
```

数据库无需回退（`SmallInteger` 和 `Integer` 存储的值兼容）。

## 影响范围

以下表基类会受到影响：
- 继承 `FieldIsDeleteSoftDeleteTableMixin` 的表（`is_delete` 列类型变更）
- 继承 `StdSyncBaseTable` 或 `StdAsyncBaseTable` 的表（**这些类已被移除**，需迁移到 `Basic*BaseTable`）
- 继承 `StdBaseCU` 或 `StdBaseDTO` 的表（**这些类已被移除**，需迁移到 `BaseCU`/`BaseDTO`）

如已自定义 `is_delete` 列类型，则软删除部分不受影响。

## 常见问题

### Q: 为什么不用 TINYINT？

A: `TINYINT` 是 MySQL 特有类型，`SmallInteger` 是 SQLAlchemy 标准类型，跨数据库兼容。

### Q: 已有数据会丢失吗？

A: 不会。`Integer` 和 `SmallInteger` 存储的 0/1 值完全兼容，只是存储空间不同。

### Q: 可以不迁移数据库吗？

A: 可以。`Integer` 列可以存储 `SmallInteger` 的值，但建议迁移以保持 Schema 一致性。
